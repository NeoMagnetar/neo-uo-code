Part 4 — Commands to support.
Supported owner commands:
- dak hunt monsters
- dak attack monsters
- dak clear monsters
- dak start monster tracking
- dak start hunting
- dak stop hunting
- dak stop tracking
- dak monster status
- waylander hunt monsters
- waylander attack monsters
- waylander clear monsters
- all hunt monsters
- companions hunt monsters
- all stop hunting

Also accept old-style:
- start tracking monsters
- start tracking all
- track monsters
- attack monsters

Command meanings:
- `track monsters`: report monsters and optionally update last monster target, but no attack unless active hunt mode is on.
- `start tracking monsters`: start read-only watch unless paired with hunt/attack command.
- `hunt monsters` / `attack monsters` / `clear monsters`: start monster-only movement/attack loop.
- `stop hunting`: stop movement/attack loop and clear active monster target.
- `monster status`: report active/inactive state, target, range, self-sustain state.

Part 5 — Valid monster target rules.
Implement a strict validator: `IsValidMonsterTarget(Mobile companion, Mobile candidate, Mobile owner)`
Must reject:
- null/deleted
- dead
- owner
- any companion
- players / PlayerMobile
- human NPCs/vendors/town NPCs
- controlled/tamed/summoned allied creatures
- blue/innocent/human-body NPCs unless old Dev evidence clearly marks them as monsters and user later approves
- targets on different map
- targets beyond configured scan range

Accept only:
- clear monster creatures according to ServUO Tracking.cs category logic or old Dev monster category evidence
- preferably hostile/aggressive BaseCreature-style mobiles
- nearest valid monster first

If classification is uncertain:
- do not attack
- report ambiguous classification

Part 6 — Monster scan/retrack.
Use actual Tracking skill and old/current Tracking.cs evidence.
Tracking skill should influence:
- scan range
- confidence
- report detail
- target acquisition confidence

Basic range model unless old code has better one:
- low Tracking: short range
- high Tracking: larger range
- GM Tracking: maximum configured range

Keep configured max reasonable for this pass:
- default max scan radius around 12–18 tiles unless old Dev used another safe value
- do not scan entire world

Loop behavior:
1. scan valid monsters in range
2. choose closest valid monster
3. move toward it if not in attack range
4. open doors if blocking/immediately adjacent during movement
5. attack when in range
6. when target dies, is invalid, or leaves range, re-scan
7. repeat until no valid monsters remain
8. stop and report "no valid monsters in range"
